# SES + SNS + EventBridge notifications

Patterns for transactional emails, event fan-out, and scheduled notifications.

## SES templated emails

### Template structure

```
email-templates/<name>/
├── template.json       # SES template resource definition
├── subject.hbs         # Handlebars subject line
├── html.hbs            # HTML body
└── text.hbs            # plain-text fallback
```

Deploy templates as `AWS::SES::Template` resources so they're version-controlled.

### Sending

```ts
import { SESv2Client, SendEmailCommand } from "@aws-sdk/client-sesv2";

const ses = new SESv2Client({});

await ses.send(new SendEmailCommand({
  FromEmailAddress: `noreply@${domain}`,
  Destination: { ToAddresses: [recipient] },
  Content: {
    Template: {
      TemplateName: "OrderConfirmation",
      TemplateData: JSON.stringify({
        firstName: order.firstName,
        orderUrl: signedUrl,
      }),
    },
  },
}));
```

Wrap in a shared helper that handles:
- Per-scope `from` address resolution
- Bounce / complaint handling via SNS
- Retry with exponential backoff on `Throttling`

## SNS topic conventions

```
<prefix>-<env>-user-notifications       # user-facing (email, SMS fan-out)
<prefix>-<env>-internal-alerts          # team alerts (Slack webhooks)
<prefix>-<env>-billing-alerts           # billing ops
```

Subscribers: email, Slack webhooks, Lambda consumers for complex routing.

## EventBridge Scheduler (delayed / recurring)

```ts
import { SchedulerClient, CreateScheduleCommand } from "@aws-sdk/client-scheduler";

const scheduler = new SchedulerClient({});

await scheduler.send(new CreateScheduleCommand({
  Name: `reminder-${entityId}`,
  GroupName: "order-reminders",
  ScheduleExpression: "at(2026-04-25T10:00:00)",
  Target: {
    Arn: reminderLambdaArn,
    Input: JSON.stringify({ scopeKey, entityId }),
    RoleArn: schedulerRoleArn,
  },
  FlexibleTimeWindow: { Mode: "OFF" },
  ActionAfterCompletion: "DELETE",
}));
```

`ActionAfterCompletion: "DELETE"` is critical — one-shot schedules pile up otherwise.

## Bounce / complaint handling

- SES publishes bounces and complaints to a dedicated SNS topic.
- A Lambda consumes, updates the contact's status, and suppresses future sends.
- Hard bounces → contact marked `hardBounce`, excluded from future sends until re-verified.

## Monitoring

- `NotificationsSent` counter, dimensioned by channel + template
- `NotificationsFailed` counter, dimensioned by error type
- `SesBounceRate` — alarm if > 5% over 24h (SES account-level metric)

## Golden rules

- ✅ All emails go through templates — no hand-built HTML strings.
- ✅ Use a shared send wrapper, not the raw SDK.
- ✅ `ActionAfterCompletion: "DELETE"` on every one-off EventBridge schedule.
- ✅ Respect the suppression list — never force-send to suppressed recipients.
- ❌ Don't send promotional content via transactional channels.
- ❌ Don't hardcode `from` addresses — resolve per scope / per env.
