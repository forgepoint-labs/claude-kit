# AWS WAF baseline

Production-grade WAF configuration for API Gateway and CloudFront.

## Rule layers (priority order)

```
100  BlockedIpSet (manual deny list)
200  AllowedIpSet (internal tools, QA runners)        [Action: Allow, ends evaluation]
300  AWSManagedRulesAmazonIpReputationList
400  AWSManagedRulesCommonRuleSet                      (with exclusions for known false positives)
500  AWSManagedRulesKnownBadInputsRuleSet
600  AWSManagedRulesSQLiRuleSet                        (only for routes that hit a DB)
700  RateBasedRule-PerIp                               (2000 req / 5 min)
800  RateBasedRule-PerEndpoint (optional)              (per-path for hot endpoints)
```

Lower priority number = evaluated first.

## IP sets

Two IP sets per environment:

- **Allowed IPs** — internal office / VPN / CI runner IPs; short-circuits evaluation
- **Blocked IPs** — manually-added abuse / scraper IPs

## AWS managed rule groups

Use as-is for the most part. Common exclusions (rules to disable because they false-positive on legit traffic):

```yaml
AWSManagedRulesCommonRuleSet:
  excluded_rules:
    - SizeRestrictions_BODY     # file uploads are large; handle size at API level
    - GenericRFI_BODY            # false-positives on some request payloads
```

Every exclusion needs a PR with reasoning. Don't exclude rules silently.

## Rate-based rules

```
RateBasedRule-PerIp:
  aggregate_key: IP
  limit: 2000           # requests per 5 minutes per IP
  action: Block
```

Per-endpoint variant for hot paths:

```
RateBasedRule-PerEndpoint:
  scope_down: <path = /api/submit AND method = POST>
  aggregate_key: IP
  limit: 60             # 1 request per 5s average
  action: Block
```

## Scope-down statements

For rules that should only apply to certain paths:

```yaml
scope_down:
  statement:
    ByteMatchStatement:
      search_string: /api/
      field_to_match: { uri_path: {} }
      positional_constraint: STARTS_WITH
      text_transformations:
        - { priority: 0, type: NONE }
```

## Logging

WAF logs go to CloudWatch Log Group or S3:

```
fields @timestamp, httpRequest.clientIp, httpRequest.uri, terminatingRuleId, action
| filter action = "BLOCK"
| stats count() by terminatingRuleId
| sort count() desc
```

## Debugging a blocked legit request

1. Get the client's IP.
2. Query WAF logs, filter by `clientIp`, identify which rule fired.
3. If managed rule false-positive: add IP to allow list (short-term), add rule exclusion (long-term, PR required).
4. If rate-based: investigate whether the client genuinely exceeded or is behind a NAT.

## Monitoring

- `BlockedRequests` per rule — top offenders in a dashboard
- Alarm on sudden spike in blocks for a single rule (attack OR false-positive after managed rule update)
- `AllowedRequests` steady state — sudden drop = WAF misconfiguration

## Golden rules

- ✅ Managed rule groups as the baseline — don't reinvent OWASP Top-10 detection.
- ✅ Rate-based rules on every public-facing endpoint.
- ✅ Allow list for internal / QA IPs.
- ✅ Every rule exclusion is justified in a PR.
- ✅ Log everything — block AND count actions for new rules.
- ❌ Don't add custom rules without starting in `Count` mode for 7+ days.
- ❌ Don't use `Block` on a managed rule group without testing in `Count` mode first.
